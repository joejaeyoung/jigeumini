바깥 흰 테두리가 EC2 한 대, 안쪽 점선 블록이 그 호스트에서 실행하는 Docker 컨테이너입니다. 운영 후보와 현재 로컬 실행을 전환해 볼 수 있습니다.

EC2 호스트 / VM Docker 컨테이너 외부 백업 서비스 후보
설계 후보Kafka는 관리형 서비스를 쓰지 않고 AZ별 EC2 한 대의 Docker 컨테이너에서 직접 운영합니다. 각 호스트에 broker와 전용 controller를 별도 컨테이너로 함께 둬 Kafka용 EC2는 총 3대입니다. 하단의 GCP 서울 요금은 같은 역할을 Compute Engine VM으로 환산한 임시 사양이며, 외부 배포나 AZ 장애 검증은 수행하지 않았습니다.

Kafka HA 범위

한 Kafka 호스트 손실은 broker와 controller 동시 손실입니다. 남은 ISR2·controller2와 복구 부하는 실제 AZ에서 검증해야 합니다.

아직 단일 실행 단위

Spring API·분석기·scheduler는 현재 한 JVM입니다. 이를 단순 복제하면 소비와 작업도 중복됩니다.

미확정 운영 값

아래 GCP 사양은 비용 비교용입니다. TLS/LB, PG 자동 전환, 중앙 경보, 실제 저장량·월 견적과 운영 SKU는 #48·#49에서 검증·결정합니다.

현재 PoC 규모 · GCP 서울 비용 비교

8대 대형 HA 비교안 · 24시간 가동

위 EC2 역할을 같은 수의 Compute Engine VM으로 옮긴 비용 비교안. Kafka VM 3대 각각에서 broker와 controller를 자체 운영하며 관리형 Kafka 비용은 없습니다. Linux E2 온디맨드, USD, 2026-10-27 조회.

현재 구현이 화면은 `deploy/compose.yaml`의 단일 호스트 배포 패키지를 나타냅니다. 웹·API·Kafka·PostgreSQL은 한 Docker 호스트에 있으며 Kafka는 combined broker/controller 1대, RF1입니다. fleet worker는 같은 서버 이미지의 별도 명령으로 실행하며 Compose 기본 서비스로 항상 켜져 있지 않습니다.
