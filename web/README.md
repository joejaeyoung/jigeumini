# 웹 UI

모노레포의 웹 영역이다. 현재는 디자인 검토용 정적 시안만 있으며 실제 API를 호출하지 않는다.

```text
web/
  design-preview/
    index.html      # 공통 화면 틀과 기능별 본문 영역
    shell.js        # 화면 등록, 주소 해석, 공통 메뉴
    app.js          # 합성 데이터와 탐색·검색·저장·상세 동작
    tokens.css      # 색상·글꼴·간격 토큰
    platform.css    # 상단 메뉴·공통 검색·반응형 레이아웃
    discovery.css   # 방송 썸네일과 카드
    styles.css      # 기본 요소와 상세 화면
    assets/         # 가상 방송 이미지
```

서버는 현재 루트의 Gradle·`src/` 구조를 사용한다. 제품 프런트엔드 도입 시 `server/`와 `web/` 경계를 기준으로 서버 경로와 루트 `scripts/`를 함께 정리한다. 이번 디자인 작업에는 서버 이동이나 프런트엔드 프레임워크 결정이 포함되지 않는다.

실행 방법은 루트 README, 진행 상태는 `docs/STATUS.md`에서 관리한다.

## 기능 확장 구조

공통 상단 메뉴·검색·페이지 제목은 유지하고 주소에 따라 본문을 전환한다. 데스크톱에서는 로고·메뉴·검색을 한 줄에, 모바일에서는 로고·검색 아래에 메뉴를 배치한다. 하단 고정 메뉴와 사이드바는 사용하지 않는다.

| 주소 | 화면 |
|---|---|
| `#/home` | 추천 방송과 현재 활발한 방송 |
| `#/explore` | 방송 탐색과 카테고리 필터 |
| `#/surges` | 반응 증가 배수 순으로 정렬한 방송 |
| `#/saved` | 브라우저에 저장한 관심 방송 |
| `#/search?q=검색어` | 공통 검색 결과 |

신규 화면은 `shell.js`의 `platformViews`에 등록한다. 메뉴·페이지 제목은 이 정의에서 생성하고, 본문 동작은 `app.js`에 연결한다. 현재 화면은 방송 목록을 공유하므로 설정으로 필터와 정렬을 바꾼다. 다른 형태의 기능은 별도 본문 렌더러를 연결하고 기존 화면 전용 영역의 표시 여부도 함께 지정한다.

검색어·카테고리는 주소에 남겨 새로고침과 뒤로 가기에서 복원한다. 제품 프런트엔드로 옮길 때는 공통 레이아웃, 기능별 화면, 서버 API 접근을 각각 분리하는 경계로 사용한다.
